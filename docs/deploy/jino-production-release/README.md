## Что размещено
Production build main, 24 карточки и шесть статей, ранее проверенный единый сайт. Домен привязан к отдельному document root `/domains/kiber-portal.ru`. PHP 8.4 выбран только для этого сайта. Действительный сертификат Let's Encrypt охватывает apex и www. Канонический адрес www сохранён. Production .htaccess и воспроизводимая упаковка — `infra/jino-production/`.

Публичные файлы (901) побайтно сверены с dist при строгом TLS и принудительном разрешении на новый origin; 12 браузерных случаев без overflow/JS ошибок/preview-плашки/noindex. Robots и advertised sitemap доступны. Конфиденциальная конфигурация хранится вне web root, mode 600, не входит в Git или пакет. Временные архив и одноразовый загрузчик удалены; загрузчик проверен как 404.

Мост использует прежний защищённый api-origin `/live`; контейнеры, recipients и credentials API не менялись. GET status=live, заведомо неполный POST={} вернул 400 до доставки. **Новая реальная заявка не отправлялась**; это не повторное доказательство приёма в CRM/Telegram. Preview остаётся dry-run. Аналитика не активировалась.

На финальном срезе публичные рекурсоры ещё расходились (Cloudflare новый, Google старый); это не полное завершение распространения. Предыдущий TTL 10800 секунд. Независимые RU GET измерения Globalping: обе проверки главной дошли до нового origin, 200/TLS authorized; CSS и изображение также 200/TLS, один CSS-запрос ещё пришёл на старый IP. Это не проверка конкретного телефона владельца.

## Проверка и воспроизведение
`npm run build:production`, затем `python3 infra/jino-production/package.py /path/to/new-empty-bundle`. Секреты не добавлять в bundle; установить приватную production.php отдельно по примеру. При наличии обратного прокси Джино определять HTTPS в RewriteCond через `HTTP:X-Forwarded-Proto`: проверка `%{HTTPS}` на этапе rewrite давала цикл, хотя PHP видел HTTPS=on. Текущая конфигурация проверена на HTTP→HTTPS и HTTPS без цикла.
