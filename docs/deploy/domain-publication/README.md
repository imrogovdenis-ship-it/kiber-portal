# Публикация КИБЕР ПОРТАЛ

Релиз PR #92 объединён в main. Сайт и API собраны штатными Dockerfile targets `web` и `api` из коммита, указанного в result.json. Не staging overlay.

## Развёртывание
- Production: https://www.kiber-portal.ru/
- apex перенаправляется на www, HTTP на HTTPS; сертификат проверен без отключения TLS.
- Только A-записи apex/www изменены с 176.57.66.246 на 38.180.37.42. Почта, wildcard, NS и другие записи сохранены.
- Рабочий compose: /home/alex/projects/kiber-production-runtime/compose.json; копия без секретов рядом.
- Секреты: отдельный локальный .env с правами 600, не хранится в Git/образах. Согласованные amoCRM + Telegram, origins только production, mode=live, production approval=true.
- Docker healthchecks, restart unless-stopped, ограниченные журналы и ресурсы, без host ports. Общий Traefik не перезапускался; прежние контейнеры не заменены.
- /sitemap-index.xml перенаправляется на рабочий /sitemap.xml через scoped middleware в compose.

## Проверено
- 35 URL карты сайта, включая 24 карточки: HTTP 200 на новом runtime.
- 8 браузерных проверок главной/G1/X2/подборки, mobile+desktop: строгий TLS, отсутствие overflow, декодирование всех изображений, 16:9 возможностей G1/X2.
- API status: 200/live. Неполный POST: 400 без отправки заявки. Нового live lead test не было; предыдущий тест доставки был подтверждён владельцем.
- Контейнеры healthy; ранее работавшие контейнеры сохранили ID.

## Распространение DNS
Авторитетные серверы Jino и 1.1.1.1 вернули новый IP. Некоторые резолверы ещё держат старый адрес (TTL 10800 секунд). Строгие HTTPS-проверки нового ingress выполнялись с сохранением Host/SNI через forced resolution, это не утверждение о полном обновлении всех клиентских DNS-кэшей. Старый сайт пока не отключён.

## Откат
Снимки зоны и сценарий точечного возврата двух A-записей сохранены в /home/alex/.hermes/state/kiber-domain-launch/ (не содержит сохранённых browser sessions). jino-rollback.mjs сверяет ожидаемые адреса перед записью и проверяет сохранность остальных записей. Запуск только после решения об откате, с доступом op из среды. DNS-откат также подвержен кэшированию; HTTPS на новом ingress при откате не отключать до окончания окна TTL.

Оставшиеся редакционные доработки роботов и аналитика отложены владельцем. Отдельные внешние alerting/backup-расписания этим отчётом не объявляются включёнными.
