# Принятый подход: карточки роботов по одной

## Последовательность
1. Прочитать текущую страницу и сохранить baseline из реально проверяемого предпросмотра.
2. Переиспользовать сохранённый Wordstat по модели; проверить конкурентов и источники характеристик до текста. Не переносить комплектации соседних моделей и чужие тарифы.
3. Зафиксировать модельный коммерческий интент и поля разрешённой редакции.
4. Переписать вводную, возможности, сценарии, FAQ и цитату, сохраняя преимущественно полное имя модели. Сокращение допустимо в ясном контексте; местоимения и «робот» лучше искусственного повтора. Синонимы добавлять редко и по смыслу, не превращая их в список.
5. Подтвердить факты; не приписывать параметры модели Кибер Гоше. Синхронизировать description, secondary keywords, seoIntent и структурированные FAQ с видимым текстом.
6. Проверить нейминг и содержательные ограничения тестами. Счётчики — редакторская страховка, не норма плотности ключей.
7. Проверить сборку/CI и сравнить HTML: допустимые изменения — текстовые поля и соответствующее SEO; каркас, цены, изображения/alt, CSS и остальные блоки заморожены.
8. Создать отдельный PR и обновить только страницу текущей модели на изолированном Джино preview. Не пересобирать весь опубликованный preview поверх других несмёрженных правок.
9. Проверить реальный HTTPS, отображение на трёх ширинах, изображения, FAQ, noindex и отсутствие overflow. Представить владельцу одну карточку.
10. После приёмки записать approval с source commit и перейти к следующей. Утверждение текста не означает merge, DNS, production или live-тест.

## Границы
Уже утверждённые Unitree G1 и Agibot X2, статьи, галереи/медиа, API и основной домен не меняются при работе над Unitree R1 без нового задания. Публикация остаётся отложенной по решению владельца.
