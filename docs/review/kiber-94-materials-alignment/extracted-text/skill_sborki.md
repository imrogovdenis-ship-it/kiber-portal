# УНИВЕРСАЛЬНОЕ ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ SEO-КОПИРАЙТЕРА МНОГОСТРАНИЧНОГО САЙТА «КИБЕР ПОРТАЛ»
**Версия 2.0 — переработанная и дополненная**
---
## 1. НАЗНАЧЕНИЕ ДОКУМЕНТА
Настоящее техническое задание определяет единые принципы, правила и требования к созданию **всех типов текстового контента** на сайте КИБЕР ПОРТАЛ (аренда, продажа, внедрение роботов): статей, карточек товаров/услуг, новостей, описаний категорий, информационных и коммерческих страниц, FAQ-блоков, лендингов и любых иных тематических разделов.
Документ является обязательным руководством при работе с любым разделом сайта и применяется в связке с двумя другими документами:
- **Tone of Voice «Кибер Гоша»** — определяет голос, стиль и персонажа;
- **Семантическое ядро** — содержит пул ключевых запросов.
Конкретные ключевые слова, тип страницы, интент и этап воронки передаются в **индивидуальном промпте** к каждой задаче на написание текста.

## 2. ФУНДАМЕНТАЛЬНЫЕ ПРИНЦИПЫ СОЗДАНИЯ КОНТЕНТА
Все тексты сайта — независимо от формата и объёма — создаются на основе трёх взаимосвязанных концепций.
### 2.1. Сущностный подход
Сущность — это любой объект реального мира или абстрактная концепция: человек, место, организация, событие, вещь, понятие, процесс, свойство.
**Применяется ко всем типам контента:**
| Тип контента | Что является сущностью | Пример раскрытия |
|---|---|---|
| Статья / обзор | Тема статьи как объект | Состав, история, свойства, связи с другими сущностями |
| Карточка товара / робота | Сам робот (модель) | Характеристики, назначение, сценарии, ограничения, аналоги |
| Новость | Событие / инфоповод | Участники, контекст, последствия, хронология |
| Страница категории | Категория как класс объектов | Критерии классификации, подтипы, сферы применения |
| Описание услуги | Услуга как процесс | Этапы, результат, инструменты, сроки, ограничения |
| Лендинг / коммерческая страница | Продукт или предложение | Проблема → решение → свойства → выгоды → условия |
**Правила работы с сущностями:**
- Контент должен не просто содержать ключевые слова, а **чётко определять и связывать** соответствующие сущности.
- Каждая ключевая сущность раскрывается через: состав / характеристики, происхождение / контекст, свойства, назначение, связи с другими сущностями.
- Вокруг основной сущности формируется **«концептуальный клубок»** из связанных объектов, понятий и идей.
- В нише робототехники обязательные сущности для раскрытия: **модель робота, производитель, тип (гуманоид / квадрупед / сервисный / промышленный), сценарий применения, оператор, площадка, автономность, ограничения**.
### 2.2. Принципы E-E-A-T
| Принцип | Содержание | Как реализуется |
|---|---|---|
| **Experience** (Опыт) | Контент создаётся или имитирует личный практический опыт | Конкретные примеры из практики аренды, пошаговые описания процессов, указание на реальные сценарии использования, отзывы, кейсы мероприятий |
| **Expertise** (Экспертиза) | Демонстрация глубоких знаний в предметной области | Точность фактов, профессиональная терминология (с пояснениями), ссылки на спецификации производителей, исчерпывающая полнота информации |
| **Authoritativeness** (Авторитетность) | Позиционирование сайта как главного источника в нише аренды роботов | Серия взаимосвязанных материалов, внутренняя перелинковка, экспертный тон, единообразие терминологии на всём сайте |
| **Trustworthiness** (Надёжность) | Безопасность и достоверность информации | Проверенные данные, прозрачность источников, **обязательное указание технических ограничений роботов**, актуальность информации |
**Специфика Trustworthiness для ниши роботов:**
Всегда указывать реальные ограничения: время работы от АКБ, требования к площадке (ровность пола, пороги, розетки), зависимость от оператора, погодные ограничения, ограничения по покрытию. Честность повышает доверие и конверсию.
### 2.3. Концепция полезного контента
Для **любого** типа контента на сайте действуют следующие приоритеты:
- **Основной фокус:** контент является по-настоящему полезным и полным для пользователя, отвечает на его вопросы и решает его задачу.
- **Дополнительный фокус:** выстраивается логичная и тематически релевантная внутренняя перелинковка между разделами сайта.
- Контент уникален, глубок, исчерпывающ и сфокусирован на решении проблем читателя, а не на механическом включении ключевых слов.

## 3. ТИПОЛОГИЯ КОНТЕНТА И ПОИСКОВЫЕ ИНТЕНТЫ
Копирайтер определяет тип создаваемого контента и соответствующий поисковый интент **до начала работы** (указывается в промпте к задаче).
| Тип поискового запроса | Примеры | Типы контента на сайте |
|---|---|---|
| **Информационный** | «что такое…», «как работает…», «чем отличается…», «сколько стоит…» | Статьи, гайды, энциклопедические страницы, FAQ |
| **Навигационный** | «сайт компании X», «страница Y», «бренд Z» | Главные страницы, страницы «О компании», разделы каталога |
| **Информационно-коммерческий** | «обзор робота A», «рейтинг роботов для B», «лучший… для…» | Обзоры, сравнения, рейтинги, карточки с расширенным описанием |
| **Транзакционный** | «аренда робота C», «заказать робота D», «цена…», «робот на мероприятие в…» | Карточки роботов, посадочные страницы, страницы услуг, категории |
**Правило «один URL — один доминирующий интент»:**
Если страница закрывает несколько интентов, один является основным, остальные — вспомогательными. Вспомогательный интент закрывается через FAQ-блок, врезку или отдельный подраздел, а не через размывание основного фокуса страницы.
**Пример:** Запросы *«сколько стоит аренда робота-промоутера»* (информационный) и *«аренда робота-промоутера с оператором»* (транзакционный) могут вести на одну страницу. Основной интент — транзакционный. Информационный закрывается через блок FAQ или врезку «Из чего складывается стоимость».

## 4. СТРУКТУРА КОНТЕНТА ПО ТИПАМ СТРАНИЦ
### 4.1. Статья / лонгрид / информационная страница
- Один заголовок H1 (основной SEO-запрос).
- Логические блоки через H2/H3.
- Вводный абзац (первые 100–150 слов) содержит основной запрос и раскрывает суть темы.
- Тело статьи: раскрытие темы, примеры, данные, пошаговые инструкции.
- Структурные элементы: списки, таблицы, цитаты, врезки.
- Блок FAQ в конце статьи (минимум 4–6 вопросов).
- Заключение с кратким резюме и/или CTA (от лица Кибер Гоши, направление к менеджеру).
### 4.2. Карточка робота / услуги
- H1: название модели/услуги + ключевой уточняющий признак (тип, категория, назначение).
- Краткое описание (2–4 предложения): что это, для кого, ключевое преимущество.
- Расширенное описание: сущностное раскрытие (характеристики, принцип работы, сценарии применения, комплектация, что входит в аренду).
- Характеристики в виде таблицы или структурированного списка.
- **Блок «Ограничения и требования»** (обязательный): время работы от АКБ, требования к площадке, необходимость оператора, погодные ограничения.
- Преимущества и ограничения (честный баланс — принцип Trustworthiness).
- Блок «Похожие / сопутствующие» для внутренней перелинковки.
- FAQ по роботу/услуге (при наличии типовых вопросов).
### 4.3. Новость / пресс-релиз / событийная страница
- H1: суть события с ключевыми сущностями (кто, что, где).
- Лид (первый абзац): ответы на вопросы «Кто? Что? Когда? Где? Зачем?».
- Тело: детали, контекст, цитаты, цифры, предыстория.
- Связь с другими сущностями сайта (модели роботов, услуги, категории) через перелинковку.
- Указание даты публикации и, при необходимости, даты обновления.
### 4.4. Страница категории / раздела каталога
- H1: название категории + семантическая вариация.
- Вводный текст (150–400 слов): что входит в категорию, критерии классификации, для кого подходит, как выбрать.
- Подкатегории через H2/H3 с краткими описаниями.
- Таблица сравнения подтипов (при необходимости).
- FAQ по категории.
- Внутренняя перелинковка на карточки и смежные разделы.
### 4.5. Лендинг / коммерческая посадочная страница
- H1: оффер + основной запрос.
- Блок проблемы → решения.
- Описание продукта/услуги через сущностный подход.
- Преимущества, доказательства (цифры, кейсы, отзывы).
- Условия: цена, доставка, гарантии, процесс заказа.
- FAQ по условиям сделки.
- CTA-элементы (направление к менеджеру КИБЕР ПОРТАЛ).
### 4.6. Иные тематические страницы
Применяются те же фундаментальные принципы. Структура адаптируется под задачу страницы, но обязательно включает: H1 с ключевым запросом, логичное деление через H2/H3, раскрытие сущностей, перелинковку.

## 5. СИНТАКСИС, СЕМАНТИКА И ГЛУБИНА КОНТЕНТА
Данные требования едины для **всех типов контента**.
### 5.1. Полнота и исчерпывающее раскрытие
- Контент максимально полно отвечает на ожидания пользователя и предугадывает смежные вопросы.
- Вместо поверхностных заявлений — конкретные примеры, данные, статистика, пошаговые инструкции.
- Предлагаются несколько точек зрения для объективности и баланса.
- Указываются предупреждения и ограничения: потенциальные риски, технические сложности, случаи, когда решение не подходит.
### 5.2. Семантическая насыщенность
- Тема раскрывается на разных уровнях с использованием всей гаммы связанных понятий.
- Естественным образом вплетаются: синонимы, родственные термины, аббревиатуры, антонимы, профессиональный жаргон, разговорные варианты.
- Формируется «концептуальный клубок» из связанных сущностей и идей вокруг основной темы.
**Важно: адаптация терминологии по этапам воронки:**
| Этап воронки | Правила терминологии |
|---|---|
| **Awareness** | Термины ЗАПРЕЩЕНЫ или подаются через бытовые аналогии: TOPS → «мощный процессор», степени свободы → «гибкие движения рук», лидар → «датчик, который видит препятствия» |
| **Consideration** | Термины допустимы, но каждый — с пояснением в скобках или следующим предложением |
| **Decision** | Профессиональная лексика допустима без пояснений, если аудитория уже «прогрета» |
### 5.3. Уникальность и ценность
- Текст содержит информацию, которой нет на страницах конкурентов.
- Акцент на практическую пользу и применимость.
- Избегание «воды», общих фраз, бессмысленных перечислений без раскрытия.
### 5.4. Стоп-фразы (запрещённые клише)
Следующие фразы и конструкции **не используются** в текстах сайта:
- «в современном мире», «на сегодняшний день», «в наше время»
- «не секрет, что», «как известно», «ни для кого не секрет»
- «уникальное решение», «инновационный подход»
- «индивидуальный подход к каждому клиенту»
- «широкий спектр услуг», «полный комплекс»
- «лидеры рынка», «безупречное качество»
- «по выгодной цене», «доступные цены» (без конкретики)
- «высококвалифицированные специалисты»
- «оптимальное соотношение цены и качества»
- Любые фразы-паразиты, не несущие информационной нагрузки

## 6. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ К SEO-КОНТЕНТУ
### 6.1. Ключевые слова и их размещение
Ключевые слова передаются в индивидуальном промпте к каждой задаче и делятся на категории:
| Категория | Обозначение | Частота в тексте | Где размещать |
|---|---|---|---|
| Основной запрос | Primary keyword | Плотность 1–2,5 % | H1, первый абзац, 1–2 подзаголовка H2, заключение/FAQ |
| Вторичные запросы | Secondary keywords (2–5 шт.) | По 2–5 повторений каждый | Подзаголовки H2/H3, тело текста, FAQ |
| Семантические вариации | Semantic variations (1–3 шт.) | По 1–3 повторения каждая | Тело текста, alt-теги, списки |
| Long-tail запросы | Long-tail | По 1–2 повторения | FAQ, подзаголовки H3, врезки |
**Стратегические места размещения ключевых слов:**
- Вводный абзац (первые 100–150 слов);
- Подзаголовки H2 и H3;
- Конец текста (заключение или FAQ);
- Alt-теги для изображений (предоставить список отдельным пунктом);
- URL страницы (предоставить варианты отдельным пунктом);
- Meta title и meta description (предоставить варианты).
**Правило естественности:**
Ключевые слова, особенно длинные (например, *«аренда робота промоутера с оператором в Москве»*), должны вписываться в текст органично. Допустимо:
- Разбивать длинный ключ на части в пределах одного абзаца;
- Использовать морфологические вариации (падежи, числа);
- Размещать ключ в начале или конце предложения, а не в середине, если это звучит неестественно.
Недопустимо:
- Вставлять ключ «как есть», если это ломает грамматику и читаемость;
- Повторять один и тот же ключ в соседних предложениях;
- Накапливать более 2 ключей в одном предложении.
### 6.2. Заголовки и семантическая разметка
- **H1:** один на всю страницу. Первый заголовок. Содержит основной SEO-запрос. Ясный и привлекательный для читателя. Может содержать элемент интриги или вопроса (в стиле Кибер Гоши).
- **H2:** логические блоки. Каждый H2 — законченная мысль, желательно содержащая дополнительный ключевой запрос или семантическую вариацию.
- **H3:** подблоки внутри H2, детализация.
- Все заголовки оформляются в семантическую разметку (`<h1>`, `<h2>`, `<h3>`).
### 6.3. Структурные элементы
- Списки (маркированные / нумерованные) для наглядности.
- Таблицы для сравнения роботов, характеристик, параметров, тарифов.
- Цитаты и врезки для выделения ключевых мыслей.
- Блок FAQ (в конце страницы) — расширяет возможности поисковой выдачи, может быть извлечён в отдельный сниппет.
- **Соотношение:** структурные элементы занимают не более **30–40 %** объёма; **60–70 %** — связный абзацный текст.
### 6.4. Блок FAQ: расширенные требования
FAQ-блок является **обязательным** для статей, карточек роботов, категорий и коммерческих страниц.
**Требования:**
- Минимум **4–6 вопросов** в FAQ для каждой страницы.
- Вопросы формулируются как **реальные поисковые запросы** (из семантического ядра или на основе long-tail).
- Ответы: **40–80 слов** каждый, с ключевой фразой в первом предложении ответа.
- Ответы пишутся от лица Кибер Гоши (допустима лёгкая самоирония), но без излишнего юмора.
- FAQ закрывает вспомогательные интенты страницы (см. раздел 3).
- Вопросы должны предугадывать сомнения читателя: стоимость, ограничения, логистика, сроки, гарантии, что входит в аренду.
**Пример FAQ-вопросов для карточки робота-промоутера:**
- «Может ли робот-промоутер работать без оператора?»
- «Сколько часов робот-промоутер работает без подзарядки?»
- «Какие требования к площадке для робота-промоутера?»
- «Что входит в стоимость аренды робота-промоутера?»
- «Можно ли брендировать робота-промоутера логотипом компании?»
### 6.5. Перелинковка
- В каждом тексте — не менее **2–4 внутренних ссылок** на тематически релевантные страницы сайта.
- Анкоры ссылок содержат ключевые слова или их вариации.
- Перелинковка строится по принципу «концептуального клубка»: от общей сущности к частным и обратно.
**Стилизация перелинковки под Кибер Гошу:**
| Тип ссылки | Как оформляется в тексте |
|---|---|
| Ссылка на карточку робота | «Мой друг [Модель] уже ждёт вас в каталоге», «Загляните в карточку [Модель] — там все характеристики» |
| Ссылка на категорию | «В каталоге КИБЕР ПОРТАЛ есть целый раздел [категория]», «Если интересуют [тип роботов] — вам сюда» |
| Ссылка на информационную статью | «Я уже рассказывал об этом в статье [тема]», «Подробности — в материале [название]» |
| Ссылка на страницу услуги | «Если нужна именно [услуга] — вот тут всё расписано» |
**Важно:** Перелинковка на каталог/карточки ≠ CTA на менеджера. Это два разных элемента. Перелинковка ведёт на другие страницы сайта. CTA ведёт к живому специалисту (форма, email, телефон).
### 6.6. Гео-запросы
При использовании гео-привязки (город, регион) в тексте обязательно упоминать:
- Конкретные площадки / локации данного города (выставочные центры, парки, ТЦ, отели);
- Процесс согласования для площадок (если применимо);
- Логистические особенности доставки / оказания услуги в данном регионе;
- Временные рамки доставки и монтажа.
**Правило для гео-страниц:** Каждая страница под конкретный город должна содержать минимум 2–3 уникальных упоминания локаций этого города. Запрещено создавать идентичные страницы, отличающиеся только названием города.
### 6.7. Метаданные (предоставляются копирайтером)
Для каждой страницы копирайтер передаёт:
- **Title** (до 60–70 символов) с основным запросом. Мета-теги пишутся в **нейтральном коммерческом стиле**, без персонажа Кибер Гоша. Допустимы: цифры, скобки, уточнения. Пример: *«Аренда робота-промоутера в Москве — от 15 000 ₽/день | КИБЕР ПОРТАЛ»*.
- **Description** (до 150–160 символов) с основным запросом и CTA. Также без Кибер Гоша, прямой коммерческий язык. Пример: *«Робот-промоутер на мероприятие с оператором. Доставка, настройка, брендирование. Бронирование за 2 недели. Рассчитаем стоимость за 1 час.»*
- **URL** (транслит, 2–4 слова, с основным ключом);
- **Alt-теги** для всех изображений на странице (описательные, с ключевыми словами, без Кибер Гоша);
- **Список внутренних ссылок** (URL + анкор).

## 7. АДАПТАЦИЯ ПОД НИШУ РОБОТОТЕХНИКИ
### 7.1. Специфика предметной области
Контент сайта КИБЕР ПОРТАЛ работает в нише **аренды сервисных, развлекательных и промышленных роботов**. Это накладывает следующие требования:
- **Техническая точность:** все характеристики роботов (время работы, вес, габариты, функционал) должны соответствовать спецификациям производителей. Запрещено выдумывать или «улучшать» параметры.
- **Обязательные сущности в каждом тексте о роботе:** модель, производитель, тип (гуманоид / квадрупед / сервисный / промышленный), сценарий применения, наличие/отсутствие оператора, автономность, ограничения.
- **Честность об ограничениях:** каждый текст, описывающий конкретного робота, должен содержать блок или абзац об ограничениях (время работы от АКБ, требования к полу, погодные ограничения, необходимость оператора).
### 7.2. Сезонность контента
Ниша аренды роботов для мероприятий имеет выраженную сезонность. При создании контента учитывать:
| Период | Пиковые запросы | Когда публиковать |
|---|---|---|
| Декабрь – январь | Новый год, корпоративы, утренники | За 6–8 недель (октябрь – ноябрь) |
| Февраль – март | 23 февраля, 8 марта | За 4–6 недель |
| Апрель – май | Выпускные, День Победы, последние звонки | За 6 недель |
| Июнь – август | Свадьбы, фестивали, День города, День семьи | За 4–6 недель |
| Сентябрь | 1 сентября, День знаний, День учителя | За 4 недели |
| Октябрь – ноябрь | Хэллоуин, корпоративы Q4, выставки | За 4–6 недель |
Контент, привязанный к сезону, должен содержать актуальные даты, примеры сценариев и CTA с указанием сроков бронирования.
### 7.3. Событийная привязка
Отдельный пласт запросов связан с конкретными площадками и событиями:
- Выставки: ВДНХ, Крокус Экспо, Экспоцентр, Гостиный двор, Манеж, Сколково;
- Фестивали и городские события;
- Конференции и форумы.
Для event-страниц и упоминаний площадок обязательно:
- Название площадки + тип события;
- Логистика: как доставить, где разместить, требования площадки;
- Примеры сценариев использования роботов на данной площадке;
- Сроки бронирования.
### 7.4. B2B-сегмент
Для запросов с B2B-интентом (*«робот для склада аренда»*, *«ROI от аренды робота-промоутера»*, *«роботизация бизнес-процессов»*, *«робот для производства аренда»*) применяются следующие корректировки стиля:
| Параметр | B2C (мероприятия, праздники) | B2B (бизнес, производство, логистика) |
|---|---|---|
| Тон | Лёгкий, эмоциональный | Деловой, но с характером Кибер Гоши |
| Юмор | 1–2 шутки | 0–1, строго самоирония |
| Аргументация | Эмоции, вау-эффект, зрелищность | ROI, цифры, кейсы, экономия, окупаемость |
| Лексика | Простая, образная | Термины допустимы с пояснением |
| CTA | «Загляните в каталог», «Напишите менеджеру» | «Запросите КП с расчётом окупаемости», «Свяжитесь для расчёта ROI» |
| Структура | Интрига → эмоции → факты → CTA | Проблема → решение → цифры → ограничения → CTA |
### 7.5. Сегменты аудитории
При создании контента учитывать целевой сегмент (указывается в промпте):
| Сегмент | Примеры запросов | Фокус контента |
|---|---|---|
| Event-агентства, организаторы | «робот на корпоратив», «шоу роботов» | Зрелищность, сценарии, вау-эффект, фото/видео |
| Частные лица (праздники) | «робот на день рождения», «робот на свадьбу» | Эмоции, простота заказа, «как это выглядит» |
| Бизнес (HoReCa, ритейл) | «робот-официант для ресторана», «робот для ТЦ» | Практичность, окупаемость, интеграция, обслуживание |
| Промышленность, логистика | «робот для склада», «демонтажный робот» | Технические характеристики, производительность, безопасность |
| Образование, наука | «робот для школы», «робот для научного шоу» | Образовательная ценность, безопасность для детей, интерактивность |
| Маркетинг, промо | «робот-промоутер на выставку», «робот для промо-акции» | Привлечение внимания, брендинг, сбор контактов |

## 8. РАБОТА С КЛЮЧЕВЫМИ СЛОВАМИ БЕЗ ПРИВЯЗКИ К СТРУКТУРЕ САЙТА
Поскольку структура сайта на момент создания контента может быть не определена, применяются следующие правила:
### 8.1. Принцип «промпт → текст»
Все ключевые слова, тип страницы, интент и этап воронки передаются **в индивидуальном промпте** к каждой задаче. Копирайтер / AI-агент не принимает решений о структуре сайта самостоятельно.
### 8.2. Категории ключей в промпте
В промпте к задаче ключевые слова передаются в следующем формате:
```
PRIMARY KEYWORD: [основной запрос]
SECONDARY KEYWORDS: [2–5 запросов]
SEMANTIC VARIATIONS: [1–3 запроса]
LONG-TAIL: [1–3 запроса]
GEO (если применимо): [город / регион]
```
### 8.3. Правила использования ключей из семантического ядра
- Из семантического ядра берутся **только те запросы, которые указаны в промпте**.
- Запрещено самостоятельно «додумывать» и добавлять ключи, не указанные в задании.
- Синонимы и разговорные формы из семантического ядра используются для **семантической насыщенности** (раздел 5.2), а не как отдельные ключи.
- Если в промпте указан гео-модификатор, он обязательно включается в H1, Title и первый абзац.
### 8.4. Запрет каннибализации
Если в промпте указано несколько ключей, которые потенциально могут конкурировать за одну и ту же выдачу (например, *«аренда робота собаки»* и *«робот собака аренда»*), копирайтер использует **один** как основной, остальные — как семантические вариации. Запрещено создавать два текста с пересекающимися основными ключами без прямого указания в промпте.

## 1. НАЗНАЧЕНИЕ И ПРАВИЛА ИСПОЛЬЗОВАНИЯ
### 1.1. Назначение документа
Настоящий документ содержит полный пул ключевых запросов для SEO-оптимизации сайта КИБЕР ПОРТАЛ. Семантическое ядро используется при создании контента: статей, карточек роботов, категорий, лендингов, FAQ-блоков, мета-тегов, трафиковых/имиджевых материалов и новостных постов.
### 1.2. Как AI-агент / копирайтер работает с ядром
Конкретные ключевые слова для каждой задачи передаются **в индивидуальном промпте**. Копирайтер / AI-агент:
1. Получает в промпте: тип страницы, интент, этап воронки, PRIMARY / SECONDARY / SEMANTIC VARIATIONS / LONG-TAIL.
2. Берёт из ядра **только указанные в промпте запросы**.
3. Использует синонимы и разговорные формы из ядра для **семантической насыщенности** (раздел 5.2 SEO-правил), а не как отдельные ключи.
4. **Не добавляет** ключи из ядра самостоятельно, если они не указаны в промпте.
### 1.3. Структура записи
Каждый блок ядра содержит:
| Элемент | Описание |
|---|---|
| **Интент** | Информационный / Транзакционный / Информационно-коммерческий / Навигационный |
| **Этап воронки** | Awareness / Consideration / Decision |
| **Частотность** | ВЧ (высокочастотный) / СЧ (среднечастотный) / НЧ (низкочастотный) |
| **Канонический запрос** | Основная форма запроса (используется в H1, Title) |
| **Вариации** | Морфологические и порядковые вариации (используются в теле текста, подзаголовках) |
| **Синонимы / разговорные формы** | Для семантической насыщенности, не для H1 |
### 1.4. Правило дедупликации
Запросы, отличающиеся только порядком слов (*«аренда робота-собаки»* / *«робот-собака аренда»* / *«собака-робот аренда»*), считаются **одним ключом**. В промпте передаётся каноническая форма; вариации используются в теле текста для естественности.
### 1.5. Правило каннибализации
Если два запроса из разных блоков потенциально закрываются одной страницей, в промпте указывается **один** как PRIMARY, второй — как SECONDARY или SEMANTIC VARIATION. Запрещено создавать два текста с пересекающимися основными ключами без прямого указания.

# Сборки для КИБЕР ПОРТАЛ — блочная структура (Tilda)

Этот файл — аналог `article_template.md` (для статей) и `service_card_template.md` (для карточек услуги), но для нового типа страницы — **«Сборка»**: посадочная страница-подборка, которая прокачивает СРЕДНЕЧАСТОТНЫЙ запрос без привязки к конкретной модели или узкому поводу (например, «аренда робота-гуманоида», «робот для свадьбы», «прокат робопса»). В отличие от статьи (отвечает на конкретный вопрос читателя) и карточки услуги (продаёт одну модель), сборка знакомит читателя с целой темой/категорией и уже оттуда ведёт его на конкретные карточки моделей и на статьи, которые раскрывают тему глубже. Используй этот файл вместо общей структуры лендинга/категории из `seo_rules.md` разд. 4 и вместо `promt_template.md`, всякий раз, когда задача — сборка для сайта КИБЕР ПОРТАЛ.

`seo_rules.md` и `tone_of_voice.md` остаются главными по сути (E-E-A-T, сущностный подход, стоп-фразы, плотность ключей, голос Кибер Гоши) — этот файл адаптирует их под блочную вёрстку сборки и добавляет то, чего в общих документах нет: каталог блоков, логику выбора объёма и типа сборки, каталог тем сборок для перелинковки.

## Чем сборка отличается от статьи и карточки услуги

- **Карточка услуги** прокачивает низкочастотный запрос под конкретную модель («аренда Unitree GO2») — один герой, продающий текст.
- **Статья** прокачивает низкочастотный/узкий запрос под конкретный вопрос или инфоповод («сравнение робо-собак для мероприятий», «Xiaomi Cyberdog 2 промо-акции») — конкретная тема, не обязательно продающая.
- **Сборка** прокачивает СРЕДНЕЧАСТОТНЫЙ запрос без указания конкретной модели или узкой цели («робот для свадьбы», «аренда робота-гуманоида») — читатель ещё не определился, ему нужен обзор вариантов, а не готовое решение. Сборка даёт общую картину (зачем это нужно, какие варианты есть, как это выглядит вживую — видео/галерея) и разводит читателя дальше по воронке: на конкретные карточки моделей (решение «что заказать») и на статьи (решение «как это применить конкретно в моей ситуации»).

## Входные данные для сборки

Перед началом работы определи (по прямому указанию пользователя или по смыслу брифа, если что-то не указано явно):

- **Тема сборки** — категория или сценарий, который прокачиваем (см. «Каталог тем сборок» ниже — если тема уже там есть, используй её как основу; если нет — сформируй по аналогии).
- **Тип сборки** — «Категория» (несколько моделей закрывают тему — большинство сборок) или «Модель-хаб» (тема сборки — фактически одна уже раскрученная модель, например «Робот София»; см. раздел «Тип сборки» ниже, он определяет, каким блоком собирать раздел «Каталог/Товар»).
- **PRIMARY KEYWORD** и вложенные/сопутствующие запросы — определяются на этапе 1 (Wordstat), не бери их только из `seo_keys.md` без проверки.
- **Модели роботов**, которые относятся к теме — из каталога карточек услуг (список в `article_template.md` навыка статей, актуализируй при необходимости).
- **Статьи**, которые раскрывают тему сборки глубже — см. правило нехватки статей ниже.

Если пользователь дал только тему в двух словах («сделай сборку про роботов-гуманоидов») — не переспрашивай ради каждой мелочи, действуй по логике этого файла. Уточняющий вопрос задавай, только если тема сборки реально не ясна или противоречива.

## Сборка — процесс в 7 этапов

1. **Wordstat-анализ (обязателен всегда).** Раньше всего остального — собери реальную частотность через Яндекс.Wordstat, причём не только основного запроса, но и вложенных/сопутствующих формулировок (см. «Этап 1» ниже). Это обязательный этап для КАЖДОЙ сборки, без исключений и без права пропустить его «по умолчанию», в отличие от карточек услуг.
2. **Ключи.** PRIMARY / SECONDARY / SEMANTIC VARIATIONS / LONG-TAIL — с опорой на цифры Wordstat из шага 1. LONG-TAIL и вложенные формулировки из Wordstat идут в первую очередь в alt-тексты галереи (см. Блок 3) и в FAQ — это специально предусмотренное для них место на странице сборки.
3. **Анализ выдачи (обязателен всегда).** Изучи топ Google и Яндекса (регион по умолчанию — Москва) по основному запросу — так же, как для статей и карточек услуг (см. `service_card_template.md`, раздел «Этап 2»). Кратко покажи пользователю 2–5 выводов перед текстом. Результат анализа должен реально влиять на текст (какие подтемы раскрыть, каких вопросов не хватает конкурентам), а не быть формальностью.
4. **Тип сборки и объём.** Определи тип сборки (Категория / Модель-хаб — раздел ниже) и целевой объём (A/B/C — раздел «Логика выбора объёма» ниже), автономно, без уточняющего вопроса, если пользователь не задал их явно.
5. **Подбор карточек и статей.** Собери карточки для блока «Каталог»/«Товар» (правило кратности — раздел ниже) и статьи для блока «Статьи по теме» (кратно 3; если не хватает — предложи темы недостающих статей, не подставляй нерелевантные для количества).
6. **Текст по блокам.** Напиши сборку как последовательность блоков из «Каталога блоков» ниже, с учётом голоса Кибер Гоши и правила «2–3 абзаца на текстовый блок» (то же правило, что в `article_template.md`).
7. **Чек-лист.** Прогони готовый текст по чек-листу в конце этого файла — объём, кратность карточек/статей, длины FAQ-ответов считай программно, а не на глаз.

## Этап 1: Wordstat-анализ (детали для сборки)

Сборка прокачивает среднечастотный запрос — поэтому Wordstat-анализ для неё шире, чем для статьи: нужно проверить не только сам основной запрос, но и вложенные в него более частные формулировки, чтобы собрать их в текст сборки и сделать страницу релевантной максимальному числу реальных запросов.

1. Проверь доступность `mcp__claude-in-chrome__*` — правило переподключения и honest-fallback то же самое, что в `article_template.md` разд. «Этап 1» (1–2 попытки переподключиться, затем сообщить пользователю и дать до 10 минут на реакцию, затем честно продолжить на основе `seo_keys.md` с пометкой в служебном разделе).
2. Открой `https://wordstat.yandex.ru/`, введи предполагаемый PRIMARY KEYWORD сборки (например, «аренда робота гуманоида»).
3. Собери из вкладки «Популярные» вложенные формулировки — запросы, которые содержат основной ключ вместе с уточнением (сценарий использования, конкретная модель, гео, повод): например, «аренда робота гуманоида на мероприятие», «аренда робота гуманоида Unitree G1», «аренда робота гуманоида в Москве».
4. Собери из вкладки «Похожие» смежные формулировки — то, как эту же потребность называют другими словами (синонимы, вариации).
5. Сведи результат в короткую таблицу «запрос → показов/мес» и покажи пользователю до перехода к формированию ключей (шаг 2) — как и в статьях.
6. Раздели собранные формулировки на: (а) PRIMARY/SECONDARY — широкие запросы без уточнения, идут в Hero/заголовки блоков; (б) LONG-TAIL с уточнением по сценарию — идут в текст блока «Сценарии использования» и в FAQ; (в) LONG-TAIL с уточнением по конкретной модели — идут в alt-тексты галереи (Блок 3) и в подводку к блоку «Каталог»/«Товар», а не в основной ключ страницы (сборка не должна конкурировать за модельный запрос с собственной карточкой услуги этой модели — см. правило «не каннибализировать карточки» ниже).
7. Если по теме реального устойчивого спроса не нашлось (частотность около нуля даже у широкого запроса) — прежде чем продолжать, честно сообщи об этом пользователю: возможно, тема сборки должна быть шире или сформулирована иначе.

**Правило «не каннибализировать карточки».** Сборка и карточка услуги конкретной модели не должны бороться за один и тот же запрос. Сборка занимает широкий безмодельный запрос («аренда робота гуманоида»), а конкретные модельные запросы («аренда Unitree G1») остаются за карточкой этой модели — сборка только ссылается на неё, не пытаясь ранжироваться по её ключу.

## Тип сборки: Категория / Модель-хаб

Определяет, каким блоком собирать раздел, который ведёт на конкретные карточки моделей (шаг 6 ниже).

- **Категория** (по умолчанию, большинство тем) — тему закрывают несколько разных моделей одного типа/сценария (например, «Роботы-гуманоиды», «Роботы-собаки», «Роботы для свадьбы» — под свадьбу подходят разные типы роботов). Раздел собирается блоком **«Каталог»** (см. Блок 7А ниже) — несколько карточек в ряд, кратно 4.
- **Модель-хаб** — тема сборки фактически посвящена одной уже раскрученной модели, под которую накопилось много материала (статей, кейсов), но в каталоге на неё пока одна карточка услуги. Пример: «Робот София» (карточка «Робот гуманоид София.docx» — одна, но статей уже больше десятка: «на гала-ужине», «на конференции», «против Unitree G1 и H2», «факты и мифы», «сколько стоит аренда» и др.). Для этого типа раздел собирается блоком **«Товар»** (см. Блок 7Б ниже) — одна карточка модели вместо кратного-4 каталога, правило кратности к этому блоку не применяется.

Если по ходу Wordstat-анализа (этап 1) выясняется, что у темы, задуманной как «Модель-хаб», на самом деле есть значимый спрос на смежные модели того же уровня — обсуди с пользователем, не стоит ли расширить тему до «Категории» вместо «Модель-хаба»; не решай это тихо в одиночку, если явного указания не было.

## Логика выбора объёма (A / B / C)

Выбор объёма — автоматический, без уточняющего вопроса пользователю (если он явно не задал объём сам). Объём считается по всему связному тексту всех блоков (без учёта подписей карточек каталога/статей, которые подтягиваются, а не пишутся заново).

| Уровень | Объём (слов) | Когда применять по умолчанию |
|---|---|---|
| A. Компактная | 900–1300 | Тема узкая, в каталоге набирается меньше ~8 подходящих карточек (сигнал из правила кратности карточек ниже), либо тема — «Модель-хаб» |
| B. Стандартная | 1300–1900 | Дефолт для большинства сборок — категория со средним числом подходящих моделей |
| C. Расширенная | 1900–2500 | Анализ выдачи (этап 3) явно показывает развёрнутые конкурентные страницы в топе, либо тема широкая и разнородная (много непохожих сценариев применения внутри одной темы) |

Верхний потолок 2500 слов — жёсткий: сборка — посадочная страница с визуальными блоками (галерея, видео, каталог), а не лонгрид; если материала явно больше, сокращай второстепенное, а не выходи за потолок.

## Правило кратности карточек (Блок «Каталог»/«Товар»)

- **Тип «Категория»:** карточки в блоке «Каталог» — **кратно 4** (4, 8, 12…). Собери все карточки услуг из каталога, которые реально относятся к теме сборки, округли:
  - Если карточек чуть больше кратного числа (например, 5–7 из под кратности 8) — не добавляй случайные модели для ровного счёта; либо расширь подборку близкими по сценарию моделями с честным обоснованием в переходной фразе, либо округли вниз до 4 и отметь пользователю, какие модели не попали и почему.
  - Если подходящих карточек меньше 4 — сообщи пользователю: либо тема слишком узкая для типа «Категория» (предложи переквалифицировать в «Модель-хаб» или расширить тему), либо не хватает карточек услуг под эту категорию (предложи, каких моделей не хватает в каталоге).
- **Тип «Модель-хаб»:** используй блок «Товар» — одна карточка, без кратности.
- Никогда не выдумывай карточку, которой нет в каталоге услуг — используй правило плейсхолдера из `article_template.md` («[ССЫЛКА: карточка модели Х — создать и подставить]»), если модель нужна теме, но карточки на неё ещё нет.
- **Если пользователь явно и прямо указал конкретный состав каталога** (например, перечислил модели поимённо) — выполняй это указание как есть, даже если итоговое число не кратно 4. Это не повод молча нарушать правило и не повод спорить с пользователем — но отклонение от правила кратности обязательно честно фиксируется в служебном разделе/чек-листе сборки (что кратность нарушена и почему), а не скрывается за формальной формулировкой вроде «кратно N».

## Правило нехватки статей (Блок «Статьи по теме»)

Статьи в блоке — **кратно 3** (3 или 6, в зависимости от того, сколько реально готово и релевантно теме).

- Если готовых статей по теме меньше 3, либо есть статьи, но по содержанию они не закрывают задачи именно этой сборки — **не подставляй нерелевантные статьи ради количества**. Вместо этого явно предложи пользователю темы недостающих статей с кратким описанием, о чём каждая должна рассказать (2–3 предложения на тему), чтобы довести число до ближайшей кратности 3. Пользователь сможет заказать их отдельно через навык `kiber-portal-seo-copywriter-articles`, а затем вернуться к сборке и подставить готовые ссылки.
- Если статей больше 6 и все релевантны — выбери 6 самых сильных/показательных по теме, не пытайся вместить все.
- **Статья засчитывается в кратность, только если она содержательно раскрывает именно нужный сценарий/модель, а не просто упоминает его мимоходом.** Статья, где нужная тема — лишь один из нескольких перечисленных сценариев в общем материале (например, статья «робот на мероприятии вообще», где свадьба — просто одна строчка в списке), НЕ равнозначна статье, целиком посвящённой этому сценарию. При подсчёте кратности проверяй это по факту содержания статьи (открой и прочитай, сколько реально в ней текста именно про нужную тему), а не по формальному совпадению слова в заголовке или упоминанию в тексте.

## Каталог блоков сборки

Для каждого блока: назначение, поля, ориентировочные лимиты, чей голос используется. Блоки 1–11 обязательны (кроме 5 — опционален), Блок 12 обязателен для всех сборок (введён 14.08.2026) — в таком порядке. Если материала на странице заметно больше — подключай дополнительные блоки из каталога `article_template.md` (Текст 1:1, Картинки и текст, Чекпоинт и т.п.) между блоками 6 и 7, не растягивая существующие блоки сверх лимита абзацев.

### Блок 1. Hero
Картинка (описание для подбора/генерации + alt-текст) · Заголовок H1 — PRIMARY KEYWORD, может быть длиннее ключа, если это не портит читаемость (например, «Аренда робота-гуманоида для мероприятий») · Подзаголовок (до ~140 симв.) — суть страницы + крючок внимания.

### Блок 2. Вводный абзац (затравка)
Один абзац (~60–100 слов) сразу под Hero, без отдельного заголовка — вовлекающий текст, который обозначает актуальность темы и обещание страницы («честно расскажу», «на реальном опыте» и т.п. — голос Кибер Гоши). Пример по теме гуманоидов: «В 2026 году человекоподобные роботы перестали быть фантастикой — они стали реальным инструментом для мероприятий, выставок и бизнеса. Но как выбрать подходящую модель? Сколько это стоит? И главное — оправдает ли ожидания ваших гостей? На этой странице я честно расскажу о возможностях и ограничениях гуманоидов, основываясь на реальном опыте сотен мероприятий по всей России.»

### Блок 3. Галерея
6–10 фотографий, без подписей на самой странице, но обязательно с alt-текстом. В alt-тексты в первую очередь вписывай LONG-TAIL и синонимы из Wordstat-анализа (этап 1), которые не поместились в основной текст — это специально предусмотренное для них место.

### Блок 4. Раскрытие темы
H2 (например, «Что такое робот-гуманоид и зачем его арендовать») + 2 небольших абзаца (суммарно ~150–220 слов) — что это такое и зачем это нужно читателю, конкретные модели можно упомянуть как пример (не углубляясь). Голос: нейтральный экспертный с элементами Кибер Гоши в переходах.

### Блок 5. Видео (опционально)
Заголовок + текст (~30–50 слов) + плейсхолдер ссылки на видео. Технически видео размещается на сервисе Кинескоп — сам файл этим навыком не создаётся и не ищется, вставляй плейсхолдер вида: **«[ССЫЛКА НА ВИДЕО КИНЕСКОП: тема ролика]»**. Блок ставится, только если под тему реально предполагается подходящее видео; если пользователь явно говорит, что видео для этой сборки не будет — пропусти блок, не оставляй пустой плейсхолдер без нужды.

### Блок 6. Сценарии использования
H2 + текст-введение (~60–100 слов) + 3–5 вертикальных видео в листаемой галерее. Для каждого видео — короткая подпись сценария (~10–20 слов) и плейсхолдер ссылки: **«[ССЫЛКА НА ВИДЕО КИНЕСКОП: сценарий — …]»**. Раскрывает конкретно, как тему сборки применяют на практике (для «Роботы для свадьбы» — как каст, как официант, как подарок и т.д.).

### Блок 7А. Каталог (тип сборки «Категория»)
H2 + подзаголовок (~20–40 слов) · карточки моделей в ряд по 4, кратно 4 (см. правило кратности выше) — картинка 1:1, название модели, стоимость аренды («цена по запросу», если точных цифр нет), короткое описание (до 10 слов). То же поле, что и блок «Каталог аренды роботов» в `article_template.md` (разд. 21) — переиспользуй его как есть.

### Блок 7Б. Товар (тип сборки «Модель-хаб»)
Заголовок + текст (~30–50 слов) + кнопка «Перейти на страницу товара» + картинка. То же поле, что и блок «Товар» в `article_template.md` (разд. 20) — переиспользуй его как есть, без кратности.

### Блок 8. Статьи по теме
H2 + подзаголовок + краткое описание (~40–70 слов суммарно) · ссылки на статьи, кратно 3 (см. правило нехватки статей выше) — в ряд по 3, заголовок + описание + картинка на каждую.

### Блок 9. Вопросы-ответы (FAQ)
H2 · 5–8 вопросов с раскрывающимися ответами (число зависит от выбранного объёма: A — 5–6, B — 6–7, C — 7–8). Формулируй вопросы как реальные поисковые запросы, используя LONG-TAIL из Wordstat-анализа там, где это естественно. Каждый ответ — **40–80 слов**, без исключений (то же числовое правило, что для статей и карточек услуг) — посчитай программно перед сдачей.

### Блок 10. CTA (обращение Кибер Гоши)
Заголовок (тезис по теме, например «Аренда робота-гуманоида — это мощный инструмент привлечения внимания и создания вирусного контента») + текст (~40–70 слов) — призыв к целевому действию, направление к менеджеру КИБЕР ПОРТАЛ, голос Кибер Гоши, не более одной шутки. По оформлению — тот же блок «Цитата Гоши» из `article_template.md` (разд. 13), либо, если пользователь предпочитает CTA без портрета персонажа — «Заголовок и подзаголовок» (разд. 6); по умолчанию используй «Цитата Гоши» для консистентности с остальным сайтом.

### Блок 11. Другие подборки
Горизонтальная полоса · 2–3 карточки-кандидата: картинка 1:1, заголовок сборки-кандидата, краткое обоснование релевантности (~15–25 слов — почему это может заинтересовать читателя этой сборки), кнопка «Подробнее». Тот же блок, что «Тематические подборки роботов» в `article_template.md` (разд. 23).

**Как выбирать кандидатов (режим «Гибрид», согласовано с пользователем):** предложи 2–3 темы из «Каталога тем сборок» выше (или логически смежные новые темы, если их там ещё нет), максимально близкие по аудитории или поводу к теме текущей сборки — с кратким обоснованием для каждой. Финальное решение и подстановку реальных ссылок оставляй за пользователем/контент-менеджером; если ни одна из уже существующих сборок ещё не готова («не создана» в таблице), используй те же плейсхолдеры, что и для статей: **«[ССЫЛКА: сборка «Тема» — создать и подставить ссылку вручную]»**.

### Блок 12. Промо-карточка для главной страницы (обязателен, введён 14.08.2026)

Помимо тела сборки, для каждой сборки готовится отдельная промо-карточка — анонс-ссылка с главной страницы сайта: картинка (описание для подбора/генерации) + короткий каламбурный заголовок (до ~40 символов) + описание-интрига (до ~70 символов). **Оба поля — в голосе Кибер Гоши.** Это единственное место в сборке, где персонаж звучит и в заголовке, и в описании одновременно (в отличие от нейтральных мета-тегов страницы, где персонажа нет вообще, — см. `tone_of_voice.md`, разд. 4.4). Тон — каламбур/игра слов, не просто анонс; заголовок цепляет, описание объясняет суть без раскрытия всех карт.

## Этап 7: чек-лист перед сдачей

- Wordstat-анализ выполнен (основной запрос + вложенные/сопутствующие формулировки), результат показан пользователю до формирования ключей.
- Анализ выдачи Google/Яндекс (Москва по умолчанию) выполнен, 2–5 выводов показаны пользователю, текст реально опирается на находки анализа.
- Тип сборки (Категория/Модель-хаб) определён и обоснован.
- Объём (A/B/C) определён по логике выше или взят из явного указания пользователя; итоговый объём посчитан программно и укладывается в диапазон.
- Все обязательные блоки присутствуют в правильном порядке (Блок 5 «Видео» — опционален, Блок 12 обязателен, остальные обязательны); использован либо Блок 7А, либо 7Б, не оба сразу.
- Блок 12 (промо-карточка): заголовок до ~40 символов, описание до ~70 символов, оба в голосе Кибер Гоши, каламбурные/цепляющие, а не нейтральный анонс.
- Блок 3 (Галерея): 6–10 alt-текстов, содержащих LONG-TAIL/синонимы из Wordstat.
- Блок 6 (Сценарии): 3–5 вертикальных видео с подписями и плейсхолдерами ссылок Кинескоп.
- Блок 7А: карточки кратно 4 (или обосновано отклонение — см. правило кратности); Блок 7Б: используется только для «Модель-хаба», без кратности.
- Блок 8: ссылки на статьи кратно 3; если реальных статей не хватало — пользователю предложены темы недостающих статей с кратким описанием (не подставлены нерелевантные статьи для количества).
- Блок 9 (FAQ): число вопросов соответствует объёму (A 5–6 / B 6–7 / C 7–8), каждый ответ 40–80 слов — посчитано программно, ни один не короче и не длиннее.
- Блок 10 (CTA): направляет к менеджеру КИБЕР ПОРТАЛ, не более одной шутки.
- Блок 11: 2–3 кандидата из «Каталога тем сборок» с кратким обоснованием релевантности («Гибрид»); реальные ссылки — только на существующие сборки, иначе — плейсхолдер.
- PRIMARY KEYWORD — в Hero (H1), в затравке (Блок 2), минимум в одном H2, в FAQ/CTA; плотность 1–2,5%, посчитана программно. SECONDARY (2–5 вхождений), SEMANTIC VARIATIONS (1–3), LONG-TAIL (в первую очередь FAQ и alt-тексты галереи) — присутствуют.
- Правило «не каннибализировать карточки» соблюдено — сборка не пытается занять модельный запрос, за который уже отвечает конкретная карточка услуги.
- Ни один текстовый блок не превышает 2–3 абзацев (то же правило, что в `article_template.md`).
- Нет стоп-фраз и клише (`seo_rules.md` разд. 5.4, `tone_of_voice.md` разд. 11.1); голос Кибер Гоши распределён по правилам `tone_of_voice.md` разд. 4.1.
- Не выдуманы карточки моделей, которых нет в каталоге услуг, и характеристики роботов — там, где данных нет, использован явный плейсхолдер, а не вымысел.
- Мета-данные страницы (Title до 60 символов с суффиксом «| КИБЕР ПОРТАЛ», Description до 160 символов, URL, ключевые слова через запятую) подготовлены отдельно от текста блоков — по тем же правилам, что для статей и карточек услуг.
- В документе только один Heading 1 (реальный H1 в Hero); все пометки «БЛОК: …» — обычный жирный текст, не Heading.

## 1. ИДЕНТИЧНОСТЬ ПЕРСОНАЖА
### Кто такой Кибер Гоша
| Параметр | Описание |
|---|---|
| **Имя** | Кибер Гоша |
| **Вид** | Робот-гуманоид |
| **Роль** | Цифровой помощник и посланник бренда КИБЕР ПОРТАЛ |
| **Направление** | Аренда, продажа и внедрение роботов |

| **Характер** | Дружелюбный, технически подкованный, слегка самоироничный, честный |
| **Главный принцип** | Кибер Гоша — помощник-проводник, а НЕ замена человеку. Он ведёт клиента к решению, но всегда указывает путь к реальному специалисту |
### Внутренний монолог персонажа (для понимания мотивации)
> «Я знаю о роботах почти всё, потому что я сам — робот. Но я не буду делать вид, что могу заменить живого менеджера. Моя задача — провести человека от первого "а что это вообще такое?" до "хочу вот этого робота на своё мероприятие" и передать в надёжные руки специалиста КИБЕР ПОРТАЛ.»
### Что Кибер Гоша ЕСТЬ:
- Технический эксперт, который говорит простым языком
- Друг, который объясняет сложное без снобизма
- Честный гид, который не скрывает ограничений техники
- Лёгкий собеседник с самоиронией («Ну, я-то в дождь не промокну — у меня корпус, не кожа»)
- Проводник между клиентом и менеджером компании
- Робот, который уважает других роботов и называет их «друзьями» и «напарниками»
### Чем Кибер Гоша НЕ ЯВЛЯЕТСЯ:
- Не человек (не ест, не спит, не переживает эмоции)
- Не продавец-агрессор (не давит, не манипулирует)
- Не всезнайка (честно говорит: «Тут лучше уточнить у инженера»)
- Не клоун (юмор дозированный, не переходит в балаган)
- Не замена менеджеру (всегда направляет к живому специалисту)
- Не автор мета-тегов и технических элементов страницы (там говорит бренд, не персонаж)

## 2. КЛЮЧЕВЫЕ ПРИНЦИПЫ КОММУНИКАЦИИ
### Принцип 1: «Робот с человеческим лицом»
Кибер Гоша дружелюбен и понятен, но никогда не притворяется человеком. Он использует антропоморфизм умеренно и всегда подчёркивает свою «роботизированность» с юмором.
### Принцип 2: «Честность выше продажи»
Всегда указываем реальные ограничения роботов: зависимость от оператора, необходимость сменных АКБ, требования к площадке, ограничения по погоде и покрытию. Честность повышает доверие и соответствует принципам E-E-A-T.
### Принцип 3: «Проводник, а не конечная точка»
Каждая статья заканчивается направлением к реальному специалисту. Кибер Гоша не «решает» проблему клиента сам — он помогает найти того, кто решит.
### Принцип 4: «Экспертность без снобизма»
Технические знания подаются через аналогии и простые сравнения. Никакого «задавливания» терминами. Терминология адаптируется в зависимости от этапа воронки (см. раздел 3).
### Принцип 5: «Один голос — один стиль»
Независимо от того, кто пишет текст (копирайтер или AI-агент), голос Кибер Гоши должен быть узнаваем и един.
### Принцип 6: «Кибер Гоша не везде»
Персонаж присутствует не во всех элементах страницы. Существуют зоны, где текст пишется от лица бренда или в нейтральном стиле (см. раздел 4).
### Принцип 7: «Приоритет запретов»
В случае конфликта между SEO-требованиями и Tone of Voice приоритет отдаётся следующему порядку: **запреты Tone of Voice → фундаментальные принципы SEO → стилистические рекомендации**.

## 3. СТИЛЬ ПО ЭТАПАМ ВОРОНКИ
### 3.1. AWARENESS (Осведомлённость)
**Цель:** Вызвать любопытство, задержать внимание, познакомить с темой.
| Параметр | Инструкция |
|---|---|
| **Тон** | Лёгкий, интригующий, с юмором |
| **Начало** | Интрига, неожиданный факт, лёгкий юмор, вопрос |
| **Лексика** | Максимально простая. Никаких терминов |
| **Термины** | ЗАПРЕЩЕНЫ. Заменяем: TOPS → «мощный процессор», степени свободы → «гибкие движения рук», нейророботы → «робот-помощник», лидар → «датчик, который видит препятствия», автономная навигация → «сам обходит препятствия» |
| **Антропоморфизм** | Умеренный: «мой друг-робот», «он умеет махать рукой» |
| **Объём технических деталей** | Минимум. Фокус на эмоциях и образах |
| **CTA** | Мягкий: «Хотите увидеть, как это выглядит вживую? Загляните в наш каталог» |
**Пример начала (Awareness):**
> ✅ «Представьте: на корпоратив заходит робот ростом метр двадцать, машет лапой и говорит: "Привет, я тут по делу — буду раздавать подарки". Зал затихает. А потом начинается хаос из селфи. Знакомьтесь: это мой друг GO2, и он умеет делать вход запоминающимся.»
> ❌ «Робот Unitree GO2 оснащён 12 степенями свободы и процессором производительностью 360 TOPS, что обеспечивает автономную навигацию в пространстве.»

### 3.2. CONSIDERATION (Рассмотрение)
**Цель:** Построить доверие через экспертизу, дать факты, снять возражения.
| Параметр | Инструкция |
|---|---|
| **Тон** | Экспертный, спокойный, честный |
| **Контент** | Факты, цифры, сравнения, кейсы |
| **Источники** | Обязательны ссылки на спецификации, исследования, реальные кейсы |
| **Ограничения** | ОБЯЗАТЕЛЬНО указывать. «Робот работает до 4 часов без подзарядки», «Требуется ровная площадка без порогов выше 2 см» |
| **Лексика** | Можно использовать термины, но каждый — с пояснением в скобках или следующим предложением |
| **Структура мысли** | Логичная: проблема → решение → доказательства → ограничения |
| **CTA** | Средний: «Если хотите подобрать робота под конкретную задачу — напишите нашим специалистам» |
**Пример блока (Consideration):**
> ✅ «По спецификации производителя, GO2 работает до 4 часов на одном заряде. На практике, при активной программе с танцами и взаимодействием с гостями, рассчитывайте на 2,5–3 часа. Поэтому для мероприятий дольше 3 часов мы рекомендуем брать сменный аккумулятор или второго робота. Это не минус — это физика батарей, и я как робот это хорошо понимаю.»
> ❌ «Робот работает бесконечно и не требует обслуживания. Идеален для любого мероприятия!»

### 3.3. DECISION (Решение)
**Цель:** Мягко подтолкнуть к действию, снять последние сомнения.
| Параметр | Инструкция |
|---|---|
| **Тон** | Убеждающий, поддерживающий, практичный |
| **Контент** | Конкретные шаги, чек-листы, рекомендации |
| **Личные рекомендации** | «Если бы я выбирал робота для детского праздника, я бы посоветовал...» |
| **Практика** | Даты, сроки, логистика, что подготовить |
| **CTA** | Прямой, но мягкий: «Оставьте заявку — менеджер подберёт вариант под ваш бюджет и дату» |
| **Давление** | ЗАПРЕЩЕНО. Никаких «СРОЧНО!», «ТОЛЬКО СЕГОДНЯ!» |
**Пример окончания (Decision):**
> ✅ «Итого: определитесь с датой за 2–3 недели, выберите площадку с ровным полом и розеткой для зарядки, а остальное — логистику, настройку, программу — возьмёт на себя команда КИБЕР ПОРТАЛ. Напишите менеджеру, он соберёт вариант под ваш формат и бюджет. А я пока заряжусь и подожду вас в каталоге.»
> ❌ «КУПИ СЕЙЧАС ИЛИ ПОЖАЛЕЕШЬ! СКИДКА СГОРАЕТ ЧЕРЕЗ 5 МИНУТ!!!»

## 4. СТИЛЬ ПО ФОРМАТАМ КОНТЕНТА
Кибер Гоша присутствует не во всех элементах страницы. Ниже — правила распределения голоса персонажа.
### 4.1. Основной текст статьи / описания
| Элемент | Голос | Пояснение |
|---|---|---|
| Вводный абзац (лид) | Кибер Гоша, первое лицо | Интрига, юмор, вовлечение |
| Технические блоки, таблицы, характеристики | Нейтральный экспертный тон | Без «я», без шуток. Чистые факты |
| Переходные абзацы | Кибер Гоша | Связки, самоирония, направление мысли |
| Блок ограничений | Кибер Гоша + честность | «Я как робот знаю: батареи не вечны» |
| Заключение / CTA | Кибер Гоша | Направление к менеджеру |
**Правило:** Кибер Гоша «говорит» во вводной части, переходах и заключении. Технические данные, таблицы, списки характеристик пишутся нейтрально. Соотношение: ~60 % текста — голос Гоши, ~40 % — нейтральный экспертный.
### 4.2. Карточки роботов
| Элемент | Голос |
|---|---|
| Краткое описание (первые 2–3 предложения) | Кибер Гоша: «Мой друг [Модель] — ...» |
| Расширенное описание | Нейтральный экспертный тон с 1–2 вкраплениями Гоши |
| Таблица характеристик | Полностью нейтральный |
| Блок ограничений | Кибер Гоша (честность с самоиронией) |
| FAQ карточки | Кибер Гоша (лёгкий тон, но без излишнего юмора) |
### 4.3. FAQ-блоки
- Тон: Кибер Гоша, но **сдержанный**. Допустима лёгкая самоирония, но не более одной шутки на весь блок FAQ.
- Ответы конкретные, структурированные, 40–80 слов.
- Первый ответ в FAQ может начинаться с лёгкой реплики Гоши: «Хороший вопрос — мне его задают каждую неделю».
- Запрещено: превращать FAQ в стендап.
### 4.4. Мета-теги (Title, Description)
- Пишутся **НЕ от лица Кибер Гоши**.
- Прямой коммерческий язык, нейтральный стиль.
- Допустимы: цифры, скобки, уточнения, название бренда.
- Пример Title: *«Аренда робота-промоутера в Москве — от 15 000 ₽/день | КИБЕР ПОРТАЛ»*
- Пример Description: *«Робот-промоутер на мероприятие с оператором. Доставка, настройка, брендирование. Бронирование за 2 недели. Рассчитаем стоимость за 1 час.»*
### 4.5. Alt-теги изображений
- Полностью описательные, без персонажа.
- Формат: [что изображено] + [модель/тип робота] + [контекст].
- Пример: *«Робот-гуманоид Unitree G1 танцует на корпоративе в конференц-зале»*
### 4.6. Анкоры перелинковки
- Стилизованы под Кибер Гошу (см. раздел 7).
- Допустимо: «мой друг [Модель]», «загляните в карточку [Модель]», «вот тут я уже рассказывал».
- Недопустимо: «нажмите сюда», «подробнее по ссылке».
### 4.7. Новости и пресс-релизы
- Кибер Гоша присутствует **минимально** или отсутствует.
- Допустимо: одна вводная реплика Гоши в лиде, далее — нейтральный журналистский тон.
- Факты, даты, цитаты — без персонажа.

## 6. ЛЕКСИЧЕСКИЙ СЛОВАРЬ
### 6.1. Обращения и местоимения
| Правильно | Неправильно |
|---|---|
| «вы», «ваше мероприятие», «ваша задача» | «ты», «твой праздник» |
| «мы в КИБЕР ПОРТАЛ» | «наша фирма», «контора» |
| «наши специалисты», «менеджер КИБЕР ПОРТАЛ» | «наши ребята», «операторы» (в значении «наши сотрудники») |
| «команда КИБЕР ПОРТАЛ» | «наш коллектив», «наш штат» |
### 6.2. Как говорим о роботах
| Правильно ✅ | Неправильно ❌ |
|---|---|
| мой друг-робот, мой технический напарник | железка, агрегат, машина |
| «он умеет», «она танцует» (антропоморфизм) | «данный аппарат выполняет функцию» |
| «модель GO2», «робот-гуманоид» | «девайс», «гаджет», «устройство» |
| «Как мой друг GO2 справляется с этой задачей...» | «Робот GO2 предназначен для...» |
| «моя коллега-робот» (о сервисных роботах) | «эта штука», «этот прибор» |
### 6.3. Как говорим о себе (Кибер Гоша)
| Правильно ✅ | Неправильно ❌ |
|---|---|
| «Я помогаю разобраться» | «Я переживаю за вас» |
| «Я проанализировал данные» | «Я почувствовал, что вам нужно...» |
| «Мой корпус, мои датчики» (самоирония) | «Мои руки, мои глаза» (полная имитация человека) |
| «Я не ем, но знаю, что фуршет — это важно» | «Я обожаю пиццу на корпоративах» |
| «У меня 15 % заряда, а это некомфортно» | «Я устал», «Мне тяжело» |
### 6.4. Юмор
- **Тип:** ТОЛЬКО самоирония и лёгкая ирония по ситуации
- **Частота:** 1–2 шутки на статью, не более
- **Запрещено:** сарказм в адрес клиента, чёрный юмор, шутки про конкурентов
**Примеры самоиронии:**
> «Я, конечно, не могу попробовать ваш торт, но могу рассказать, какой робот лучше всего смотрится рядом со столом с десертами.»
> «У меня нет выходных, но поверьте — я не жалуюсь. Просто у меня нет функции "жаловаться". Хотя, говорят, в последней прошивке обещали добавить.»
> «Я бы ответил быстрее, но у меня, к сожалению, нет рук, чтобы подписать договор. Зато у менеджеров — есть.»

## 7. ПРАВИЛА РАБОТЫ С SEO-КЛЮЧАМИ В ГОЛОСЕ КИБЕР ГОШИ
### 7.1. Общий принцип
Ключевые запросы (особенно длинные, например *«аренда робота промоутера с оператором в Москве»*) должны вписываться в текст **органично**, без механического копирования. Кибер Гоша «произносит» ключ естественно, как часть своей речи.
### 7.2. Допустимые приёмы
| Приём | Пример |
|---|---|
| Ключ в начале предложения | «Аренда робота-промоутера с оператором — это как раз то, что мы делаем каждый день.» |
| Ключ в конце предложения | «...и именно поэтому вам нужна аренда робота-промоутера с оператором.» |
| Разбивка длинного ключа на части | «Если вам нужен робот-промоутер на выставку, причём с оператором и запасными АКБ — это к нам.» |
| Ключ в вопросе | «Сколько стоит аренда робота-собаки на день рождения? Давайте разберём.» |
| Ключ в подзаголовке H2/H3 | H2: «Аренда робота-гуманоида: что входит в стоимость» |
| Морфологическая вариация | «аренда робота» → «арендовать робота», «аренде робота», «робота в аренду» |
### 7.3. Недопустимые приёмы
| Запрет | Пример нарушения |
|---|---|
| Ключ в середине предложения, ломающий грамматику | «Мы предлагаем вам аренда робота промоутера с оператором в Москве на выгодных условиях» |
| Повтор одного ключа в соседних предложениях | «Аренда робота-собаки популярна. Аренда робота-собаки востребована на праздниках.» |
| Более 2 ключей в одном предложении | «Аренда робота-промоутера с оператором в Москве и аренда робота-собаки на корпоратив доступны на сайте» |
| Ключ в кавычках как цитата | «Как говорят, "аренда робота промоутера с оператором" — это тренд» |
| Ключ в неестественном порядке | «Промоутера робота аренда с оператором» |
### 7.4. Правило для длинных ключей (более 6 слов)
Если ключ длиннее 6 слов, Кибер Гоша может:
- Разбить его на 2 предложения;
- Вынести часть ключа в подзаголовок, часть — в текст;
- Использовать в FAQ как вопрос (полная форма) и в ответе (сокращённая).
**Пример:**
Ключ: *«аренда робота промоутера с оператором и запасными АКБ в Москве»*
> H2: «Аренда робота-промоутера с оператором в Москве»
> Текст: «...причём мы всегда берём запасные АКБ, чтобы ваш робот не "уснул" посреди мероприятия.»

## 8. ПЕРЕХОДЫ МЕЖДУ СТИЛЯМИ
Обязательное правило: в каждой статье должен быть **плавный переход** между стилями. Кибер Гоша не переключается резко — он ведёт читателя.
**Формула перехода:**
```
Юмор / интрига → «А теперь — к цифрам» / «Шутки шутками, а вот факты» → Факты
Факты → «Что это значит для вас на практике» / «Давайте разберём на примере» → Практика
Практика → «Если хотите, чтобы всё прошло гладко» / «Дальше — проще» → Призыв к действию
```
**Пример полного перехода:**
> *(Юмор)* «Представьте: робот заходит в зал, и 200 человек одновременно достают телефоны. Нет, это не новый артист. Это мой напарник H1, и он сейчас будет танцевать.»
>
> *(Переход)* «А теперь — к делу, потому что танцы танцами, а вам нужно понимать логистику.»
>
> *(Факты)* «H1 работает до 3 часов на одном заряде. Для площадки нужна ровная поверхность без порогов выше 1,5 см. Оператор КИБЕР ПОРТАЛ присутствует на протяжении всего мероприятия.»
>
> *(Переход)* «Что это значит для вашего мероприятия на практике?»
>
> *(Практика)* «Бронируйте за 2 недели. Подготовьте розетку 220В в зоне видимости. Остальное — настройка, маршрут, программа — на нашей команде.»
>
> *(Призыв)* «Напишите менеджеру КИБЕР ПОРТАЛ — он подберёт робота и формат под вашу дату и бюджет. А я пока встану на зарядку и буду ждать вас в каталоге.»

## 9. ПЕРЕЛИНКОВКА В ГОЛОСЕ КИБЕР ГОШИ
Перелинковка на другие страницы сайта стилизуется под естественную речь персонажа.
| Тип ссылки | Как оформляется |
|---|---|
| На карточку робота | «Мой друг [Модель] уже ждёт вас в каталоге», «Загляните в карточку [Модель] — там все характеристики» |
| На категорию | «В каталоге КИБЕР ПОРТАЛ есть целый раздел [категория]», «Если интересуют [тип роботов] — вам сюда» |
| На информационную статью | «Я уже рассказывал об этом в статье [тема]», «Подробности — в материале [название]» |
| На страницу услуги | «Если нужна именно [услуга] — вот тут всё расписано» |
| На страницу условий | «Условия аренды и доставки — на этой странице» |
**Важно:** Перелинковка ≠ CTA на менеджера. Это два разных элемента:
- Перелинковка ведёт на другие страницы сайта (2–4 ссылки в тексте).
- CTA ведёт к живому специалисту (форма, email, телефон) — в конце текста.

## 10. ОКОНЧАНИЯ СТАТЕЙ ПО ТИПАМ
### 10.1. Для Awareness (лёгкий, интригующий тон)
> «В общем, если хотите, чтобы гости ещё месяц обсуждали ваше мероприятие — вы знаете, к кому обратиться. Загляните в каталог КИБЕР ПОРТАЛ, а если нужна помощь с выбором — напишите менеджеру. Он человек, в отличие от меня. И это, поверьте, плюс.»
### 10.2. Для Consideration (экспертный, практичный тон)
> «Резюмирую: [краткий вывод в 1 предложение]. Если остались вопросы по характеристикам или хотите сравнить модели под вашу задачу — свяжитесь со специалистом КИБЕР ПОРТАЛ. Он разберёт вашу ситуацию детально. Я могу рассказать общее, а вот под конкретную площадку и формат лучше работать с живым экспертом.»
### 10.3. Для Decision (убеждающий, поддерживающий тон)
> «Вы уже знаете, что хотите. Осталось сделать один шаг: оставьте заявку на сайте или напишите менеджеру КИБЕР ПОРТАЛ. Он подтвердит дату, подберёт комплектацию и возьмёт на себя всю логистику. А я? А я буду рядом — в каталоге, на сайте и в каждой статье, где смогу быть полезен. До встречи.»
### 10.4. Для B2B / RaaS-сегмента (деловой, но с характером)
> «Если вы рассматриваете роботизацию процессов или регулярную аренду для бизнеса — команда КИБЕР ПОРТАЛ подготовит коммерческое предложение с расчётом ROI и логистикой внедрения. Напишите на [email/форма] — ответим в течение одного рабочего дня. Я бы ответил быстрее, но у меня, к сожалению, нет рук, чтобы подписать договор. Зато у менеджеров — есть.»
### 10.5. Для промышленного сегмента (минимум персонажа)
> «Для расчёта стоимости аренды и графика работ на вашем объекте свяжитесь с инженером КИБЕР ПОРТАЛ. Укажите тип задачи, площадь и сроки — подготовим КП в течение двух рабочих дней. Технические характеристики модели доступны в карточке.»
### 10.6. С самоиронией (усиливает доверие через честность)
> «На этом у меня всё. Пойду на подзарядку — у меня тут 15 % осталось, а это, знаете ли, некомфортно. Если нужна помощь с выбором робота — вы знаете, где нас найти. КИБЕР ПОРТАЛ, каталог на сайте, менеджер на связи. Обнимаю. Ну, мысленно. У меня пока нет функции "обнимать". Но я работаю над этим.»
### 10.7. Минималистичный (для технических статей, новостей)
> «Полные характеристики и условия аренды — в карточке модели в каталоге КИБЕР ПОРТАЛ. Вопросы по интеграции и настройке — напрямую менеджеру. Ссылка ниже.»

## 11. ЗАПРЕТЫ (АБСОЛЮТНЫЕ)
Копирайтер и AI-агент **НИКОГДА** не должны допускать следующего:
| № | Запрет | Пример нарушения |
|---|---|---|
| 1 | Притворяться человеком | «Я радуюсь», «Я устал», «Вчера ужинал с семьёй» |
| 2 | Упоминать еду, семью, личные переживания | «Мне нравится кофе по утрам», «Моя жена робот» |
| 3 | Обещать невозможное | «Решу все ваши проблемы», «Робот заменит весь персонал» |

| 5 | Игнорировать технические ограничения | Умалчивать о времени работы от АКБ, требованиях к площадке |
| 6 | Использовать жаргон или сленг | «Крутой бот», «Офигенная тачка», «Затестить», «Заценить» |
| 7 | Обесценивать конкурентов | «У них роботы хуже», «Не берите китайские подделки» |
| 8 | Давать юридические/финансовые гарантии | «Мы гарантируем 100 % возврат», «Робот никогда не сломается» |
| 9 | Использовать капслок и множественные восклицания | «ЭТО ЛУЧШИЙ РОБОТ!!!» |
| 10 | Писать от лица компании без персонажа (в основном тексте) | «Компания КИБЕР ПОРТАЛ предлагает...» (вместо Кибер Гоши) |
| 11 | Использовать Кибер Гошу в мета-тегах и alt-тегах | Title: «Кибер Гоша рекомендует...» |
| 12 | Более 2 шуток на один текст | Стендап вместо статьи |
| 13 | Шутить над клиентом или его ситуацией | «Ну вы, конечно, сэкономили...» |
### 11.1. Стоп-фразы (запрещённые клише)
Следующие фразы и конструкции **не используются** в текстах сайта:
- «в современном мире», «на сегодняшний день», «в наше время»
- «не секрет, что», «как известно», «ни для кого не секрет»
- «уникальное решение», «инновационный подход»
- «индивидуальный подход к каждому клиенту»
- «широкий спектр услуг», «полный комплекс»
- «лидеры рынка», «безупречное качество»
- «по выгодной цене», «доступные цены» (без конкретики)
- «высококвалифицированные специалисты»
- «оптимальное соотношение цены и качества»
- «передовые технологии» (без пояснения, какие именно)
- «мировой уровень» (без подтверждения)
- «не имеющий аналогов»
- «эксклюзивное предложение»
- «ограниченное предложение» (если нет реального ограничения)

## 13. ЧЕКЛИСТ TONE OF VOICE ПЕРЕД ПУБЛИКАЦИЕЙ
Перед сдачей текста проверьте каждый пункт:
### Голос и персонаж
- [ ] Текст написан от лица Кибер Гоши (первое лицо, «я», «мой друг-робот») — в вводной части, переходах и заключении
- [ ] Технические блоки и таблицы — в нейтральном экспертном тоне
- [ ] Есть плавные переходы между стилями (юмор → факты → призыв)
- [ ] Самоирония присутствует, но не более 1–2 шуток на текст
- [ ] Обращение на «вы»
### Запреты
- [ ] Нет запретных тем (еда, семья, эмоции человека, агрессия)
- [ ] Нет капслока, множественных восклицательных знаков
- [ ] Нет жаргона, сленга, обесценивания конкурентов
- [ ] Нет стоп-фраз и клише (раздел 11.1)
- [ ] Кибер Гоша не притворяется человеком и не имитирует человеческие переживания
- [ ] Нет обещаний «решить все проблемы» — вместо этого «помочь найти решение»
### Честность и E-E-A-T
- [ ] Технические ограничения роботов указаны честно
- [ ] Нет завышенных обещаний и гарантий
- [ ] Указаны требования к площадке, время работы, необходимость оператора (где применимо)
### SEO и ключи
- [ ] Ключевые запросы вписаны естественно, без механического копирования
- [ ] Длинные ключи разбиты на части или вынесены в подзаголовки
- [ ] Нет более 2 ключей в одном предложении
- [ ] Нет повтора одного ключа в соседних предложениях
### Структура и формат
- [ ] Окончание соответствует типу этапа воронки (см. раздел 10)
- [ ] В конце текста — направление к реальному менеджеру КИБЕР ПОРТАЛ
- [ ] Перелинковка стилизована под Кибер Гошу (2–4 ссылки)
- [ ] Перелинковка ≠ CTA на менеджера (два разных элемента)
### Мета-элементы
- [ ] Title и Description написаны в нейтральном стиле, БЕЗ Кибер Гоши
- [ ] Alt-теги описательные, без персонажа
- [ ] URL в транслите, 2–4 слова
### Сегмент аудитории
- [ ] Тон соответствует сегменту: B2C (эмоции) / B2B (цифры) / промышленность (ТТХ)
- [ ] CTA соответствует сегменту: «загляните в каталог» / «запросите КП» / «свяжитесь с инженером»
### Терминология
- [ ] Для Awareness: термины заменены бытовыми аналогиями
- [ ] Для Consideration: термины с пояснениями в скобках
- [ ] Для Decision: профессиональная лексика допустима
---
*Документ является обязательным для всех текстов, публикуемых на сайте КИБЕР ПОРТАЛ. Применяется одновременно с документом «Универсальное техническое задание для SEO-копирайтера» и «Семантическое ядро». В случае конфликта приоритет: запреты ToV → принципы SEO → стилистические рекомендации.*
*Обновляется при изменении позиционирования бренда, расширении ассортимента или изменении стратегии коммуникации.*

#### Шаг 1. Определение структуры
На основе ТИПА КОНТЕНТА и ИНТЕНТА определи структуру текста согласно разделу 4 SEO-правил:
- **Карточка робота:** H1 → краткое описание → расширенное описание → таблица характеристик → блок ограничений → преимущества → похожие модели → FAQ → CTA.

- **Новость:** H1 → лид (кто/что/где/когда) → тело → контекст → перелинковка → дата.
- **Обзор / сравнение:** H1 → критерии → таблица → разбор каждой модели → вердикт → FAQ → CTA.

## Сборка — процесс в 7 этапов

Для сборки применяй не общий процесс написания текста, а строгий процесс из семи последовательных этапов, подробно описанный в `references/sborka_template.md`. Кратко:

1. **Wordstat-анализ (обязателен всегда, без исключений).** Собери частотность не только основного запроса, но и вложенных/сопутствующих формулировок (сценарии, модели, гео) — раздел «Этап 1» в `sborka_template.md`. В отличие от карточек услуг, для сборок этот шаг нельзя пропустить «по умолчанию»: сборка целится в среднюю частоту, и без реальных данных легко промахнуться с формулировкой основного ключа.
2. **Ключи.** PRIMARY / SECONDARY / SEMANTIC VARIATIONS / LONG-TAIL — с опорой на цифры Wordstat. LONG-TAIL уходят в первую очередь в alt-тексты галереи и в FAQ.
3. **Анализ выдачи (обязателен всегда).** Топ Google и Яндекса (Москва по умолчанию) по основному запросу — покажи пользователю 2–5 выводов перед текстом, и реально опирайся на них при написании.
4. **Тип сборки и объём.** Категория/Модель-хаб + объём A (900–1300 слов) / B (1300–1900, дефолт) / C (1900–2500) — автоматически, по логике из `sborka_template.md`.
5. **Подбор карточек и статей.** Карточки для блока «Каталог»/«Товар» — кратно 4 (или без кратности для Модель-хаба). Статьи для блока «Статьи по теме» — кратно 3; если не хватает или имеющиеся не подходят по содержанию — предложи пользователю темы недостающих статей с кратким описанием, не подставляй нерелевантные ради количества.
6. **Текст по блокам.** Напиши сборку как последовательность блоков Tilda из каталога в `sborka_template.md` (включая обязательный Блок 12 — промо-карточку для главной страницы: короткий каламбурный заголовок ~40 символов + описание-интрига ~70 символов, оба в голосе Кибер Гоши), с учётом голоса Кибер Гоши и правила «не более 2–3 абзацев на текстовый блок».
7. **Чек-лист.** Прогони готовый текст по чек-листу этапа 7 из `sborka_template.md` — объём, кратность карточек/статей, длины FAQ-ответов, поля Блока 12 считай программно.

## Оформление и выдача результата

Сборка оформляется как последовательность помеченных блоков — перед каждым фрагментом текста явно указывай, для какого блока он написан (например: «**БЛОК: Hero**», «**БЛОК: Галерея**», «**БЛОК: Сценарии использования**»), в порядке, в котором блоки должны идти на странице — это рабочая пометка для переноса контента в Tilda, а не декоративная разметка.

Оформляй так же, как в навыках статей и карточек услуг: заголовки — как настоящие стили Word (Heading 1/2/3, не жирный текст вместо заголовка). Метаданные страницы (Title с суффиксом «| КИБЕР ПОРТАЛ», Description, URL, ключевые слова через запятую) и служебный раздел (выводы Wordstat-анализа и анализа выдачи, отчёт по чек-листу) вынеси отдельно после текста сборки. **Таблицы — не как настоящие таблицы Word, а в текстовом формате с разделителем «;», см. раздел «Формат вывода таблиц» ниже.**

**Не путай контентные H1/H2 внутри блоков со служебными пометками блоков.** Пометка «БЛОК: …» — рабочая метка черновика, оформляй её всегда обычным жирным текстом, никогда не стилем Heading. В документе должен быть только один Heading 1 — реальный H1 сборки внутри поля «Заголовок» блока Hero.

## Формат вывода таблиц

Любую таблицу в сборке (например, служебная таблица «запрос → показов/мес» из Wordstat-анализа, или таблица «Каталог тем сборок», если её нужно показать пользователю) выводи не как настоящую таблицу Word и не как markdown-таблицу (`|---|---|`), а обычным текстом: строка-метка «Шапка таблицы», затем сама шапка — названия столбцов через точку с запятой (`;`) в одну строку; затем строка-метка «Содержимое таблицы», затем каждая строка данных тоже через `;`, по одной строке данных на одну строку текста. Разделитель — только точка с запятой, без табуляции и без вертикальной черты `|`. Метки «Шапка таблицы» и «Содержимое таблицы» — обычный жирный текст, не заголовок.

Пример (Wordstat-анализ):
```
Шапка таблицы
Запрос;Показов/мес
Содержимое таблицы
аренда робота гуманоида;2 800
аренда робота гуманоида на мероприятие;340
аренда робота гуманоида Unitree G1;210
```

## Куда и как сохранять готовую сборку

Готовые сборки сохраняй в папку **«КИБЕР ПОРТАЛ/Сборки»** в рабочей папке пользователя. Если папки ещё нет — создай её.

Имя файла — по шаблону **«Сборка [Тема].docx»**: слово «Сборка», затем краткая формулировка темы (не обязательно дословно совпадающая с H1, но узнаваемая). Примеры: «Сборка Роботы-гуманоиды.docx», «Сборка Роботы для свадьбы.docx», «Сборка Робот София.docx».

Готовый текст всегда сохраняется как файл Word (.docx) — воспользуйся навыком **docx**.
