# КИБЕР ПОРТАЛ — короткая owner-сводка по Claude contracts

## Смысл
Мы переводим работу Claude из режима “напиши красивый текст” в режим “заполни поля утверждённого сайта”.

## Главное правило
- Дизайн/порядок approved блоков не меняется.
- Claude отдаёт только контент по адресам вроде `blocks.hero.h1`, `blocks.faq.items[0].answer`.
- Hermes потом просто раскладывает поля в шаблон.

## Три типа страниц
1. `robot_card` — фиксированный порядок блоков карточки робота.
2. `compilation` — фиксированный порядок блоков подборки.
3. `article_detail` — фиксированное начало и окончание, но Claude может выбрать нужные optional middle-блоки.

## Почему это связано с SEO-аудитом
Аудит показал 0 fail, но warnings почти везде: ключи в title/H1/first block, secondary keywords, schema/FAQ/breadcrumbs/CTA. Поэтому эти поля встроены в контракт как обязательные.

## Что смотреть при согласовании
- Достаточно ли блоков для карточек роботов.
- Правильно ли названы блоки подборок.
- Достаточно ли свободы Claude в статьях.
- Не нужно ли сделать какие-то блоки optional/required иначе.

## Что не утверждается
Production, DNS, analytics, secrets, live lead routing и массовая публикация не входят в это утверждение.
