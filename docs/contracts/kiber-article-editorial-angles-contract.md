# KIBER article editorial angles contract

Status: **owner_approved_working_rule**  
Owner approval note: Александр утвердил, что новые статьи не должны механически повторять один вход вроде «роботу нужна роль». Перед написанием нужно выбрать уникальный editorial angle из списка ниже или создать новый, если ни один не подходит.
Scope: `/articles/...` editorial planning, first H2/SEO intro, block map and diversity QA.

## Purpose

The article template can reuse approved visual blocks, but the article's **editorial entry** must be chosen per topic. Do not make every scenario article start with the same idea: «робот работает лучше, когда у него есть роль». That idea is useful inside many multi-robot articles, but it is not the only possible first move.

Before writing or rewriting an article, choose one primary entry angle and optionally one secondary angle. Record the choice in the SEO passport/review notes when practical.

## The 20 approved entry-angle options

| # | Angle | Use when | First-block logic | Avoid |
|---:|---|---|---|---|
| 1 | Problem / failure mode | The topic has a common mistake | Start with what usually goes wrong and how to avoid it | Generic scolding |
| 2 | Guest journey | Event experience matters | Walk through what the guest sees from entrance to final memory | Dry logistics |
| 3 | Atmosphere / mood | Theme, holiday, party, brand vibe | Explain what the event should feel like and how robots support that feeling | Decoration-only copy |
| 4 | Product attention | Product/idea launch, showroom, stand | Start from the product/message; robot is an attention tool, not the hero | Making robot overshadow product |
| 5 | Choice between formats | Several formats/models compete | Help reader choose between 2–5 options | Fake comparisons |
| 6 | Single best fit | One model/role is clearly strongest | Narrow quickly to the best-fit model/format and explain conditions | Pretending one fit covers all cases |
| 7 | Sequential scenario | Event has phases | Structure by time: before/during/after or entrance/stage/finale | Repeating “roles” without sequence |
| 8 | Zone map | Venue has distinct zones | Structure by entrance, stage, bar, photo, stand, lounge | Turning every article into a zone table |
| 9 | Buyer checklist | Searcher is close to request | Start with what to prepare to get an accurate offer | Making the whole article a checklist |
| 10 | Risk / limitation | Overpromises are common | Lead with what not to promise and how to set safe expectations | Negative tone only |
| 11 | Visual proof | Seeing the robot matters | Start from what the buyer needs to picture in real life | Gallery filler |
| 12 | Content-after-event | Photos/videos/social proof matter | Explain what remains after the event: clips, photos, souvenir, report | Forgetting live guest experience |
| 13 | Audience-specific | Children, executives, partners, visitors differ | Start from who is in the room and what they will respond to | Stereotypes |
| 14 | Venue constraints | Site conditions decide feasibility | Start from floor, space, light, sound, flows and timing | Overly technical intro |
| 15 | Budget / value logic | Reader worries about value | Explain where one robot is enough and where a combined program pays off | Prices/guarantees without source |
| 16 | Story / narrative | Event is a launch, ceremony, reveal | Build an arc: setup → surprise → interaction → memory | Forced drama |
| 17 | Educational explainer | Topic asks “how it works” | Explain mechanism in simple terms before selling | Sales-first tone |
| 18 | News/event recap angle | Article is about a real exhibition/news/event | Start from what happened, why it matters and what organizers can learn | Inventing facts or eyewitness details |
| 19 | Trend / cultural context | Topic is a style/trend like cyberpunk, AI, robotics | Start with the cultural meaning and then translate it into event decisions | Abstract essay without practical steps |
| 20 | Decision tree | Search intent is broad/uncertain | Lead with “if you need X, choose Y; if Z, choose W” | Too many branches |

## If none fits

If none of the 20 angles fits the article:

1. Define a new angle in one sentence: what reader situation requires it?
2. Add it to the article SEO passport/review notes as `custom_editorial_angle`.
3. If the angle is likely reusable, add it to this contract before or after delivery.
4. Do not force an article about exhibitions, news, a real event, a venue, a partner case or an unusual circumstance into a robot-role pattern.

## Diversity gate before preview

Before preview handoff, compare the new article with at least the last 3–5 article drafts/current index entries.

Check:
- the first H2/SEO intro is not the same formula as recent articles;
- first 2–3 H2s reveal the specific topic, not a generic robot rule;
- “role/scenario/zone” language is used only where it improves the reader decision;
- Gosha joke is not a variant of the previous Gosha joke;
- FAQ and checklist are shaped by this article's intent, not copied from the previous article;
- if the article is multi-robot, each robot still gets a clear function, but that function does not have to be the first editorial thesis.

## Practical rule

The recurring rule «give each robot a role» remains valid for multi-robot scenario articles, but it should usually appear as one supporting block among several possible structures. The first editorial move must be chosen from the topic's reader need: product, mood, event route, risk, audience, venue, trend, news/event context, or another justified angle.
